1.3 Чеклист за production-ready плащания

  • Paysera production credentials конфигурирани (PAYSERA_PROJECT_ID, PAYSERA_SIGN_PASSWORD)
  • PAYSERA_TEST_MODE=false за production
  • Stripe production API keys (ако се използва Stripe)
  • Webhook URL-та регистрирани в Paysera dashboard
  • Webhook URL-та регистрирани в Stripe dashboard
  • SSL сертификат валиден за callback URL-та
  • Тестово реално плащане завършено успешно (€1-2 тест)
  • Refund на тестовото плащане завършен
  • Wallet balance коректен след всички операции
  • Payment failure alert конфигуриран в Sentry
  • Transaction logging работи за audit trail
  • PCI DSS compliance потвърден (Paysera/Stripe обработват карти → SAQ A)

2.3 Тестове за натоварване (Load Testing)

Инструменти: k6 (препоръчителен) или Artillery за HTTP load testing; pgbench за database stress testing.

Baseline Load Test

  • Virtual Users: 50 concurrent
  • Duration: 10 минути
  • Ramp-up: 30 секунди
  • Endpoints: health (100/s), login (20/s), offers (50/s), venues (30/s), receipts (10/s)

Peak Load Test

  • Virtual Users: 200 concurrent
  • Duration: 5 минути
  • p95 < 500ms, p99 < 2s
  • Error rate < 1%, No memory leaks

Stress Test

  • Virtual Users: 500 concurrent
  • Duration: 3 минути
  • Цел: Намиране на breaking point
  • Мониторинг: CPU, Memory, DB pool, Response curve

Payment-Specific Load Test

  • Virtual Users: 20 concurrent
  • Duration: 5 минути
  • Create intent → webhook → wallet credit
  • Verify: Няма загубени транзакции

Раздел 3

Онбординг на тестови партньори (5-10)

3.1 Цели на тестовия онбординг

  1. Валидиране на данни – дали партньорският профил се попълва коректно
  2. UX feedback – дали процесът е интуитивен за реални бизнеси
  3. Стикер тестване – дали BOOM стикерите работят в реална среда
  4. Receipt обработка – дали OCR разпознава реални касови бележки
  5. Cashback flow – дали cashback-ът се кредитира правилно

3.2 Процес за тестови онбординг

Стъпка 1: Подписване на споразумение ├── NDA (ако е необходимо) ├── Тестово споразумение (без финансови ангажименти) └── Определяне на контактно лице Стъпка 2: Заявка за данни ├── Име на бизнеса (BG + EN) ├── Категория (ресторант, кафене, хотел, магазин, и т.н.) ├── Описание (BG + EN) ├── Лого (мин. 400×400px, PNG/JPG) ├── Cover image (мин. 1200×600px) ├── Адрес + GPS координати ├── Работно време ├── Телефон, имейл, уебсайт └── Контактно лице Стъпка 3: Въвеждане в системата ├── Създаване на Partner запис (status: PENDING) ├── Създаване на Venue запис(и) ├── Създаване на 2-3 тестови оферти ├── Генериране на BOOM стикер QR кодове └── Качване на лого и cover image в S3 Стъпка 4: QA ревю ├── Проверка на данните за коректност ├── Визуална проверка на офертите ├── Тест на стикер сканирането ├── Тест на receipt обработката └── Активиране (status: ACTIVE) Стъпка 5: Тестов период (2 седмици) ├── Реално сканиране на стикери от тест-потребители ├── Submit на реални касови бележки ├── Събиране на feedback (форма или интервю) └── Документиране на бъгове и проблеми Стъпка 6: Обратна връзка ├── Structured feedback форма ├── UX проблеми → backlog ├── Data issues → корекции └── Решение: продължава / напуска пилота

Трети страни

5.4 API contract consistency чеклист

  • Всички API endpoints връщат consistent error format { error, message, statusCode }
  • JWT token expiry е синхронизиран (access: 15min, refresh: 7d)
  • Mobile deep link scheme boomcard:// регистриран в app.json
  • CORS разрешава origin на мобилното приложение
  • API versioning е консистентен (/api/v1/ или /api/)
  • Date formats са ISO 8601 навсякъде
  • Pagination format е еднакъв ({ data, total, page, limit })
  • File upload limits са еднакви (receipt images < 10MB)

8.2 Регистрация в Търговски регистър

  • Избор на фирмено име (проверка за уникалност в ТР)
    Основно: BoomCard ЕООД | Резервни: BoomCard Bulgaria ЕООД, BoomCard BG ЕООД
  • Определяне на седалище и адрес на управление
  • Подготовка на учредителен акт / дружествен договор
  • Определяне на капитал (мин. 2 лв. за ЕООД)
  • Специмен от подписа на управителя
  • Декларация по чл. 13 ал. 4 от ЗТР
  • Декларация по чл. 141 ал. 8 от ТЗ (за управителя)
  • Заявление А4 за вписване в ТР
  • Заплащане на държавна такса (55 лв. онлайн / 110 лв. на хартия)
  • Подаване чрез портала на ТР (с КЕП) или чрез адвокат

КОД ПО КИД: 62.01 – Компютърно програмиране
Алтернативно: 63.11 – Обработка на данни, хостинг

8.3 След регистрацията

  • Получаване на ЕИК (единен идентификационен код)
  • Регистрация по ДДС (задължителна при оборот > 100 000 лв.)
    Или доброволна регистрация (за приспадане на ДДС от разходи)
  • Откриване на фирмена банкова сметка (UniCredit, DSK, Postbank, Revolut Business)
  • Регистрация в НАП (Национална агенция за приходите)
  • Регистрация в НОИ (ако ще има наети лица)
  • Назначаване на счетоводител / счетоводна къща

8.4 Допълнителни регистрации

  • КЗЛД – Регистрация като администратор на лични данни (cpdp.bg)
  • КЗП – Запознаване с изискванията (ЗЕТ, право на отказ 14 дни)
  • Домейни: boomcard.bg (основен), boomcard.com (защитен)
